How each part gets built in GPUI

  • Resizable sidebars. A 6 px drag strip between two flex children and a stored width in pixels. Dragging under the minimum collapses the side. You already have sidebar.rs and right_panel.rs to hang this on.
  • Scale. Every size here is in em. In GPUI that is the window's rem size, so one setting scales text, icons and spacing together.
  • Backdrop. Wayglim is a WebGL shader, which GPUI cannot run as it is. The light route is to port the look you pick there to a small Rust function, draw it at about one sixth of screen resolution (Smooth above does exactly that) and let paint_image stretch it. That is under 1 MB of memory and it stops when the window is not in front. Today and sessions share one image; sessions draw it dimmer.
  • Glass cards. The vendored GPUI has no backdrop blur. Because only our own backdrop sits behind a card, the same look comes from painting a pre-blurred copy of the backdrop inside the card, then a tint and a one-pixel highlight on top. Text sits on a 65 to 85 percent tint so it stays readable over the brightest part of the ribbon.
  • Light and dark. One token table per theme, as theme.rs already does. The backdrop is drawn as coloured dots on white in light mode.
  • File tree and editor. The tree is cheap. The editor is the largest new piece: GPUI ships no code editor, so this starts from your text_area.rs and needs syntax colours and large-file handling added.
  • Agent icons. The SVGs from svgl.app ship in assets/ and draw with svg().path().
  • Scrolling. No permanent scrollbars. Each scrolling area draws a thin thumb only while you scroll or hover, which GPUI does with a scroll handle and one painted bar.
  • Resources and ports. Windows reports every listening port with the process that owns it, and Glasscode already tracks each session's process tree, so tying a port or a memory figure to a worktree is a lookup. Kill ends that process tree.
  • Voice orb. The same trick as the backdrop: a small image drawn in Rust, smooth or dithered, driven by the microphone level. The voice panel itself is not ported to Windows yet.
  • Today cards. A wrapping grid that drops from three columns to two to one as the centre narrows. Drag a sidebar to see it.

What first run can import, and from where

  • Projects. Recent folders from Cursor and VS Code (their recently-opened list under %APPDATA%), folders Claude Code and Codex already worked in (~/.claude/projects, ~/.codex/sessions), plus a scan of a folder you choose for git repos. Cursor and Zed do the same on their own first run for VS Code settings.
  • Claude accounts. Glasscode already starts each session with its own CLAUDE_CONFIG_DIR. First run can list every login it finds, including accounts saved by claude-swap in ~/.claude-swap-backup, and you tick the ones to use.
  • Other agents. Codex, Gemini CLI and Cursor's agent are detected by their command and login folder. GitHub comes from gh auth status. Linear needs a key.
  • Skills, plugins, MCP servers. Read in place from ~/.claude and each repo's .claude, so every agent session keeps what it has today.
  • Sign-in during setup. Ticking an agent that has no valid login starts its own login command and opens the browser at once; setup waits for it. Expired logins are flagged with a Sign in button.
  • These paths need checking against each tool on Windows before they are built.
